# 0005 第二轮事件契约、隐私与生命周期

## 决策

### 事件与配置契约

- `EventAction` 继续严格表示规范约定的 22 个交互动作。
- `EXPOSE` 是 SDK 自有的唯一系统动作，通过 `SystemEventAction.EXPOSE` 表达；
  `EventType` 是二者的封闭联合，不接受集成方任意扩展字符串。
- `businessType`、`serviceName` 与 eventCategory 各段必须以字母开头且仅含
  字母数字；eventCategory 必须有 2–3 段。eventPath 必须是非空、无空段的
  `组件[.实例].控件[:文本]` 形态。
- 无效 init 不进入已初始化态；无效事件、hook/beforeReport 丢弃及内部异常均
  不向集成方抛出，并只记本地聚合诊断。

### data-track-* 覆盖

- 属性名集中在 `auto-tracking/attributes.ts`。空字符串按未设置处理。
- `data-track-ignore` 任一祖先存在即忽略整棵子树。
- name/control 取最近祖先的非空值，优先于零侵入推断；module 取文档中首个
  非空覆盖，优先于 URL；row-label 先取当前行，再取所属表格，可为表头名或
  0 起列下标。无有效覆盖时才进入现有推断规则。

### 生命周期

- `destroy` 是完整 teardown：自动采集、Observer、Panel、dispatch 订阅、
  hooks、module inferrer、平台适配器、就绪缓冲、预初始化缓冲与 config 全部
  清理。平台适配器可实现 `teardown`。
- destroy 后允许再次 init。destroy 与下一次 init 之间的 `track` 等同首次
  init 前调用，进入 200 条有界预初始化缓冲；destroy 本身会丢弃当时尚未发送
  的缓冲。自定义 adapter/hook/订阅需在新一轮重新注册。
- `onDispatch` 返回幂等 unsubscribe；自动采集返回实例 handle。不同 Tracker
  或不同 root 不共享 active/节流状态。
- 本地 diagnostics 是 Tracker 实例级累计值，不含事件 payload、不联网；
  destroy 后仍可读取，便于复盘，随后 re-init 继续累计。

### 隐私、去重与就绪

- 默认脱敏覆盖 eventPath、字符串 eventValue 和 eventCustom 全部深层字符串；
  mask 内部失败时整条事件安全丢弃，不放行原文。
- 第二轮曾把平台附加上下文限制为 timestamp、去掉 query/hash 的 pageUrl 和
  appId；第三轮因缺少真实平台资料，已由 ADR 0006 收紧为 SDK 不自动添加上下文，
  仅把 appId 交给显式 contract 决定是否映射。
- 去重只由上报路由器负责，窗口为 300ms。指纹包含 EC/ET/EP/EV/eventCustom，
  eventCustom 对象键排序后序列化，因此键顺序不同但内容相同仍视为重复，内容
  不同则保留。
- 同名 adapter 只保留第一个。未就绪 adapter 独立缓冲 200 条，溢出丢最旧；
  async setup resolve 或 `onReady` 会主动 flush，后续 dispatch 仅作为兜底探测。
  脚本失败或长期未就绪时不重试联网、不无限增长，保持有界等待至就绪或 destroy。

## 后果

此决策收紧了此前 `TrackEvent.eventType: string` 的宽松类型，但与 CONTEXT 中
“eventType 为规范动作”的领域语言一致，并消除了 EXPOSE 的隐式例外。可靠性
与隐私失败均采用 fail-closed；诊断只提供聚合计数，避免诊断本身形成泄露通道。
