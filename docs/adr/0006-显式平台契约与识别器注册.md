# ADR 0006：显式平台契约与识别器注册

状态：已接受（2026-07-10）

## 背景

仓库和公开资料均未提供可唯一确认的 Furion/UEM 前端 SDK 文档、版本、全局对象、
上报方法、payload 或真实集成环境。原实现按 `report/track/send` 候选方法探测并
临时透传字段，这会把未经证实的猜测固化成公共行为。实际共享组件库的名称、版本、
DOM fixture 与浏览器范围也尚未提供，无法可靠选择并实现 2–3 个库专用识别器。

## 决策

1. Furion/UEM 内置平台适配器只负责全局实例生命周期和安全脚本加载。集成方必须
   提供 `PlatformSdkContract`，显式实现 readiness、文档规定的方法调用和字段映射。
   缺少契约时适配器不就绪且不加载脚本。
2. SDK 交给契约的 `TrackEvent` 已完成统一校验和脱敏。SDK 不自动添加 timestamp、
   page、session、user 或 device；契约和平台对其自行补充的上下文负责。
3. 自加载脚本仅接受无凭据 HTTPS URL，可配置精确 origin 白名单、SRI、CSP nonce、
   CORS 和 referrer policy。`cdnUrl` 作为一个兼容周期的别名保留。
4. `registerRecognizer` 成为正式顶层扩展 API。高 priority 先执行，同 priority 按
   注册顺序；重名和 `generic` 保留名安全拒绝；注销幂等并恰好执行一次 teardown；
   `generic-dom` 永远最后。
5. 不在缺少采用证据时虚构组件库识别器。先锁定注册契约、checkbox/radio/select、
   自定义 Element root 和 ShadowRoot；取得真实 fixture 后再按垂直切片接入。
6. 本轮保留原顶层兼容导出，不增加 advanced 子入口。

## 后果

- 平台接入从“运行时猜测”改为“编译期可见、可独立测试的契约”，首次迁移需要集成方
  提供其已核验实现。
- 旧的无 contract 配置不再发送事件；事件仍按既有有界就绪缓冲语义处理并产生聚合
  diagnostics。该变化是消除伪造平台签名所必需的安全修正。
- 真实平台 smoke 和组件库专用识别器继续受外部资料阻塞，不能用 fake fixture 宣称
  已完成；本仓库只把可验证的本地契约 smoke 纳入 CI。
